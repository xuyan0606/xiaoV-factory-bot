## 2. 分布式事务策略选择指南

```
+------------------+       +------------------+       +------------------+
|     TCC 模式      |       |    SAGA 模式      |       |  最终一致性      |
|  (Try-Confirm/   |       |  (正向+补偿)      |       |  (消息队列)      |
|   Cancel)        |       |                  |       |                  |
+------------------+       +------------------+       +------------------+
        |                         |                         |
  适用场景:                 适用场景:                 适用场景:
  - 采集任务分配            - 批次生产流程           - 设备状态变更通知
  - 资源预留                - 跨服务编排            - 日志/报表异步更新
  - 短事务，高一致性要求     - 长事务，可补偿        - 低一致性要求
        |                         |                         |
  优点:                    优点:                    优点:
  - 强一致性                - 可处理长事务           - 高吞吐
  - 明确的资源预留           - 每个步骤可独立失败     - 松耦合
  - 适合高竞争资源           - 补偿逻辑清晰          - 易扩展
        |                         |                         |
  缺点:                    缺点:                    缺点:
  - 需要实现 Try/Cancel     - 补偿逻辑复杂          - 最终一致，有窗口期
  - 资源锁定时间成本         - 不支持读已提交        - 需处理幂等
  - 不适合长事务             - 调试困难             - 需处理死信
```

### 策略选择矩阵

| 业务场景 | 推荐模式 | 理由 |
|---------|---------|------|
| 采集任务分配 (谁采集哪个设备) | **TCC** | 资源需要预留，避免冲突 |
| 批次生产流程 (配料→发酵→离心→干燥→包装) | **SAGA** | 长流程，每步可补偿 |
| 设备状态变更通知 | **最终一致性** | 无需强一致，允许短暂延迟 |
| 库存扣减 | **TCC** | 高竞争资源，需精确控制 |
| 工单状态流转 | **SAGA** | 多步骤，需完整回滚 |
| 报表数据同步 | **最终一致性** | 异步处理，重试机制 |
| 告警通知 | **最终一致性** | 高吞吐，允许丢失 |

### 幂等性检查 — 通用原则

所有分布式事务操作的**必备**能力：

1. **唯一标识**: 每个操作使用全局唯一的 txn_id 或 idempotency_key
2. **去重存储**: 记录已处理的操作标识 (Redis/DB)
3. **幂等处理**: 重复请求返回相同结果，不产生副作用
4. **重试安全**: 失败重试不会导致业务数据异常

## 3. 混沌工程最佳实践

### 核心原则

```
1. 最小爆炸半径
   - 先在测试环境验证
   - 从非关键服务开始
   - 逐步扩大范围

2. 自动化恢复
   - 所有实验必须可自动恢复
   - 实验前自动备份
   - 实验后验证恢复

3. 持续实验
   - 定期运行混沌实验
   - 纳入 CI/CD 流水线
   - 建立系统韧性基线

4. 可观测性
   - 实验期间加强监控
   - 记录所有故障注入和恢复
   - 生成结构化实验报告
```

### 实验分类与优先级

| 优先级 | 实验类型 | 场景 | 建议频率 |
|--------|---------|------|---------|
| P0 | 网络延迟 | MQTT Broker 延迟、API 网关延迟 | 每日 |
| P0 | 进程杀死 | 数据采集服务、消息消费者 | 每日 |
| P1 | CPU 压力 | 边缘网关、数据聚合服务 | 每周 |
| P1 | 内存压力 | 缓存服务、3D 渲染引擎 | 每周 |
| P2 | 数据损坏 | 传感器数据篡改、配置文件损坏 | 每月 |
| P2 | 磁盘 I/O | 日志写入、数据库写入 | 每月 |

### 实验流程

```
+--------+     +-----------+     +----------+     +----------+
| 计划   |---->| 备份状态   |---->| 注入故障 |---->| 观察行为 |
+--------+     +-----------+     +----------+     +----------+
                                                      |
                                                     v
                                              +----------+
                                 <--FAIL---   | 验证恢复 |
                                              +-----+----+
                                                    | PASS
                                                    v
                                              +----------+
                                              | 生成报告  |
                                              +----------+
```

### 恢复验证清单

| 检查项 | 描述 | 验证方法 |
|-------|------|---------|
| 进程存活 | 所有关键进程应自动重启 | `ps aux | grep <service>` |
| 端口可达 | 服务端口应正常监听 | `nc -zv localhost <port>` |
| 数据完整 | 数据库读写正常 | SQL SELECT 1 |
| 队列处理 | 消息队列无积压 | 检查队列深度 |
| API 响应 | REST/WS 接口正常 | HTTP 200 状态码 |
| 3D 渲染 | 前端页面正常加载 | 浏览器无报错 |
